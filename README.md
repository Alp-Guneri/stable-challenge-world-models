# Stable Challenge World Models

The [challenge guide](CHALLENGE.md) covers the dataset and the submission contract. The challenge website is published from `docs/`. Official scores are generated by the organizers’ evaluator. Uploaded model files remain private. Participant emails appear only when anonymity is disabled.

## Training and local evaluation

Run `uv sync --locked` and unpack the challenge corpus as described in the guide. The Linux lockfile uses CUDA 13.0 wheels. A CUDA 13-compatible driver is needed for GPU training with that environment. The corpus, checkpoints, and local ONNX exports are ignored by Git.

| Trainer | Architecture |
|---|---|
| [`example_train.py`](example_train.py) | Stacked-frame CNN with an action-conditioned residual MLP. Optional action encoder and training-only motion head. |
| [`train_strong.py`](train_strong.py) | Residual CNN with frame differences, pixel coordinates and an 8×8 feature map. Optional training-only motion head. |
| [`train_lewm.py`](train_lewm.py) | Compact ViT with a causal action-conditioned transformer. Trained end to end with latent prediction and SIGReg. |

A validation fraction of 0.1 reserves the final 333 episodes of the already shuffled corpus. The reference trainer defaults to the full corpus. Set `--val-frac 0.1` to reproduce the holdout ablations.

```bash
uv run example_train.py --floor --out floor.onnx
uv run train_lewm.py --corpus corpus --arch reference --steps 6000 \
  --lr 1e-3 --weight-decay 1e-4 --workers 4 --out ref_holdout.onnx

# Matched 24k-step reference and motion-head runs. Repeat both with --seed 1.
uv run example_train.py --corpus corpus --val-frac 0.1 --steps 24000 \
  --precision 16-mixed --seed 0 --out reference.onnx
uv run example_train.py --corpus corpus --val-frac 0.1 --steps 24000 \
  --precision 16-mixed --seed 0 --motion-loss-weight 0.25 --out motion.onnx
# Use --action-encoder for the action ablation or add it to the motion command for both.

uv run train_strong.py --corpus corpus --steps 40000 --out strong.onnx
# Add --motion-loss-weight 0.25 for the Strong motion-head run.

uv run train_lewm.py --corpus corpus --steps 40000 --workers 6 \
  --dim 96 --dim-head 24 --patch 8 --enc-depth 6 --enc-mlp 384 \
  --pred-depth 6 --pred-mlp 384 --proj-hidden 384 --out lewm_long.onnx
# For the equal-window comparison, use the same LeWM settings with --precision 16-mixed.
# Pair --batch-size 128, 256, and 512 with --steps 8000, 4000, and 2000, respectively.

uv run test_submission.py strong.onnx
uv run proxy_eval.py strong.onnx reference.onnx motion.onnx --val-frac 0.1 \
  --floor floor.onnx --reference ref_holdout.onnx --out proxy-results.json
uv run action_diagnostic.py reference.onnx motion.onnx --out action-results.json
```

The [proxy evaluator](proxy_eval.py) uses 1,332 windows across the 333 reserved episodes by default. Top-1 is the fraction of rollouts that retrieve their actual future embedding by cosine similarity. Motion R² is the ridge probe score for predicting the center of moving pixels from the rollout embedding. The blend averages normalized Top-1 and motion R² using the local floor and 6k holdout reference as anchors. These are public-corpus measurements. The leaderboard uses its own private data and tasks.

Full-corpus scores are in-sample. Strong had the best mean retrieval on held-out episodes, while the narrow seed-1 reference reached 62.99% at 25 steps in a 5.7 MiB export. The motion head improved 25-step retrieval by 2.18 percentage points on seed 0 and reduced it by 2.18 points on seed 1. In the equal-window LeWM sweep, batch 128 led on retrieval. The larger batches used fewer optimizer updates and had a larger effective SIGReg penalty under the same loss coefficient.

The 40k LeWM total training loss plateaued near 0.314 after 30k steps. [Loss curve](experiments/lewm-long-loss.png) · [Logged metrics](experiments/lewm-long-metrics.csv)
